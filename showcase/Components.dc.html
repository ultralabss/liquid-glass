Buttons, inputs and selection

Every control is built on ULGlass (buttons) or the inset well (fields). Hover, focus and pressed columns are forced with the internal forceState prop so all states are visible at once; the live column reacts to the pointer and keyboard. One section is mounted at a time. The governor refracts up to 150k px² of glass per viewport (max 30 surfaces); small controls stay full, big surfaces drop to lite first.

Selection (2b)

Boxes, thumbs, the segmented capsule and triggers are glass (small controls stay full under the area budget). Rows sit on a dark scrim (data-ul-surface="solid", not glass) so labels pass 4.5:1 while the glass still refracts the stage. The right column repeats them inside a glass panel, where they flatten.

Lens bubble

Press and hold any control: a glass rounded rectangle grows out of the flat thumb or indicator, follows the pointer with an elastic two-edge stretch, and shrinks back once it has settled. Switch: drag to set, decided on release. Tabs and segmented: hold and drag, release selects. Slider: the value commits immediately, the thumb glides on the follow spring and the tooltip moves in the same frame.

Containers + overlays (2c)

Cards and panels are rigid (pointer light + rim); only sm interactive cards are elastic. Every overlay is ULAnchoredSurface: one morph, one scroll policy, one overlay stack. Motion proof: motion-test · scroll proof: scroll-bench.

Data (2d)

Panels (KPI cards, stat tiles, table, chart) are one lite glass surface each; rows, cells and plot marks are never glass. Basic / rich and intensity scale the material. Glass appears only in controls (select-all, buttons), overlays (row actions menu) and the chart value tooltip. The table has a sticky header, sorting, selection, three densities, grid keyboard navigation (one tab stop; arrows, Home / End, Ctrl+Home / End, PageUp / PageDown, Space selects), skeleton loading and an empty state.

Dashboard blocks

Composition of existing parts only: filter bar, columns menu (also on header right-click), flat cell renderers, a bulk bar that pours in from the bottom edge while rows are selected, time range + refresh, copy field with mask, status, banners, usage, error state, description list.

Actions

One core (useAsyncAction + ULActionButton): idle → loading → success | error → idle, minimum loading time, double clicks ignored, icon and label swap inside the button, width morph, success ring, error shake. Feedback through the anchored tooltip and one polite live region.

ACTION TIME SCALE Wave, ring, swaps, check, width morph and the success / error timers only. Lens timings stay at 1×.

Live data

A mock socket feeds two keyed stores (one commit per frame). Rate, burst, disconnect, reconnect, duplicates and a slow network are simulated in the page; nothing leaves the browser.

Charts

One shared core (src/charts): scales, axes, legend chips with ULCheckMark, snapped value tooltip, keyboard navigation, data table, CSV / copy. Each chart is one lite glass panel; the plot never refracts. Cards mount lazily and animate only when visible. Faster single page: probe-charts.

Charts (advanced)

Radial, gauge, radar, scatter / bubble, heatmap + calendar, funnel, histogram, treemap, zoom / brush, streaming and the linked demo. Same demos as probe-charts ?adv; the section mounts when scrolled near and each card animates only while visible.

Forms

ULField owns label, description and error for any control; ULInputGroup is one inset well with addons, inline buttons, counter and clear. Flat paint, no glass inside the well.

Navigation, layout + typography (3D)

Hover card, menubar, navigation menu, native select, calendar, aspect ratio, resizable panels, carousel and typography. Overlays use the shared anchored morph; nothing here adds glass of its own.

Feedback + structure

Alerts, alert dialog, confirm popover, toggle group, separator, kbd, item, collapsible and scroll area. In-flow parts are flat or tinted paint; glass stays on overlays and controls.
